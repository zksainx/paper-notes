## Background

SOSP '25 broadens the LLM-infrastructure surface from kernels and schedulers to correctness, memory, retrieval, and production operations. The list below includes papers whose accepted-paper descriptions directly target LLM training/inference or a serving primitive that is explicitly evaluated for LLMs.

## Methodology

| Theme | Papers and system contribution |
| --- | --- |
| Training reliability | **Robust LLM Training Infrastructure at ByteDance**: production fault handling and robustness mechanisms; **Mycroft**: dependency tracing through collective communication; **DCP**: dynamic context parallelism for input-dynamic long-context training; **TrainVerify**: equivalence-based verification for distributed training; **Sailor**: automating training over dynamic, heterogeneous, geo-distributed clusters. |
| Inference memory | **DiffKV**: differentiated KV management with parallel compaction; **Jenga**: heterogeneous memory management for LLM serving; **IC-Cache**: in-context caching; **PrefillOnly**: an engine specialized for prefill-only applications. |
| Serving and placement | **Pie**: programmable serving for emerging LLM applications; **Aegaeon**: GPU pooling for concurrent serving; **KTransformers**: CPU/GPU hybrid MoE inference. |
| Retrieval and edge | **HedraRAG**: co-optimizes generation and retrieval; **METIS**: quality-aware RAG configuration adaptation; **Characterizing Mobile SoC**: heterogeneous mobile LLM inference. |

### Key Design Choices

- Move from opaque request queues to explicit state: KV blocks, context partitions, collective dependencies, and model placement.
- Separate correctness checks from the fast path using tracing, equivalence, or selective verification.
- Exploit heterogeneity instead of hiding it: CPU/GPU memory, mobile SoCs, pooled GPUs, and geo-distributed clusters are treated as scheduling inputs.

## Experiment

The accepted-paper page provides complete titles and authors but uneven public abstracts. The strongest quantitative evidence available from linked public material includes: Mycroft's fine-grained collective dependency tracing; DCP's improved utilization under dynamic long contexts; TrainVerify's equivalence checking for distributed runs; METIS's quality/latency trade-off adaptation; and KTransformers/PowerInfer/LoongServe's hardware-aware serving gains. For papers without a public abstract on the conference page, this note records the system contract rather than fabricating a number.

## Limitation

- SOSP accepted-paper metadata is not a substitute for the final proceedings PDF; several entries require reading the artifact or paper for exact baselines.
- Production infrastructure papers may report internal traces or deployment details that are not fully reproducible.
- RAG and mobile-inference results are highly workload and hardware dependent.
