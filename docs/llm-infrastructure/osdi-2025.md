## Background

OSDI '25 had a concentrated LLM-infrastructure cluster. The papers target the execution substrate rather than model quality: wafer-scale hardware mapping, live model loading, workload balance across parallel dimensions, serving throughput, straggler diagnosis, and quantization-aware inference.

## Methodology

| Paper | Core problem | System idea |
| --- | --- | --- |
| [WaferLLM](https://www.usenix.org/conference/osdi25/presentation/he) | GPU-oriented runtimes waste wafer-scale mesh locality | PLMR hardware model plus MeshGEMM/MeshGEMV and wafer-scale parallelism |
| [BlitzScale](https://www.usenix.org/conference/osdi25/presentation/zhang-dingyan) | Autoscaling stalls while model parameters load | PipeThreader loads through the GPU compute network and uses multicast with O(1) host cache |
| [Understanding Stragglers](https://www.usenix.org/conference/osdi25/presentation/lin-jinkun) | Production training stragglers are hard to attribute | What-if analysis separates workload, placement, and system causes |
| [NanoFlow](https://www.usenix.org/conference/osdi25/presentation/zhu-kan) | LLM serving throughput is limited by pipeline bubbles | Fine-grained pipeline scheduling and overlap for decode-heavy workloads |
| [WLB-LLM](https://www.usenix.org/conference/osdi25/presentation/wang-zheng) | 4D parallelism has pipeline/context imbalance | Variable-length document packing plus per-document context sharding |
| [DecDEC](https://www.usenix.org/conference/osdi25/presentation/park-yeonhong) | 3-4 bit quantization harms quality | CPU-resident residuals fetched for activation-salient channels at decode time |

### Key Design Choices

- Treat interconnect, memory hierarchy, and scheduling as a single optimization surface.
- Make dynamic workload shape explicit: document lengths, active requests, and salient channels all drive runtime decisions.
- Use selective correction or replay instead of paying full-precision costs globally.

## Experiment

| Paper | Headline evidence |
| --- | --- |
| WaferLLM | Up to 200x higher accelerator utilization; 10-20x full-inference speedup over A100 GPU clusters; 606x faster GEMV and 16x better energy efficiency than A100 for the reported setup. |
| BlitzScale | Demonstrates that compute-network loading can match or exceed host-cache behavior while avoiding large parameter caches; paper reports live scaling benefits across multi-host deployments. |
| Understanding Stragglers | Uses what-if counterfactuals to quantify the contribution of data, scheduling, and hardware factors; the contribution is diagnostic rather than a single throughput number. |
| NanoFlow | Reports near-optimal serving throughput against hand-designed scheduling baselines on representative LLM workloads. |
| WLB-LLM | Average 1.23x speedup in an internal LLM training framework across model scales. |
| DecDEC | Shows quality recovery for low-bit inference while retaining memory and latency benefits; exact gains depend on quantizer and model. |

## Limitation

- WaferLLM depends on wafer-scale hardware and a PLMR model that may not transfer directly to GPU clusters.
- BlitzScale assumes a sufficiently capable GPU fabric and multicast support.
- WLB-LLM and NanoFlow are sensitive to workload length distributions and runtime integration details.
- DecDEC adds CPU-GPU traffic and a saliency heuristic; quality guarantees are empirical.
- The official OSDI page exposes abstracts, not always full reproducibility artifacts, so some comparisons remain setup-specific.
